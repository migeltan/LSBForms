## 🟢 Step 1 — Installation

- Run once per machine. Self-elevates, installs Chrome locally into
  `.chrome-cache/`, and registers the Windows Service.

| Step | Instruction                                             |
| :--- | :------------------------------------------------------ |
| 1    | Open PowerShell as Administrator                        |
| 2    | Find the path of the `pdf-service` folder               |
| 3    | Open the `pdf-service` folder and run the command below |

**Paste / run this code:**

```powershell
cd pdf-service
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

> [!TIP]
> Success looks like this green line:
> `PdfRenderService is installed and running at http://127.0.0.1:4488`
>
> Safe to re-run anytime — `install.ps1` always does a clean reinstall.

> [!NOTE]
> The `daemon/` folder (`pdfrenderservice.exe`, `.xml`, `.exe.config`,
> log files) is entirely generated by this install step and is
> `.gitignore`d — never commit it. It bakes in an **absolute path** to
> this project on this machine, so a copy from another machine (or
> another folder location) will not work.

---

## 🔵 Step 2 — Run

- Everything in this step needs to be executed in elevated terminals with full access.
- Right-click PowerShell/VS Code → **Run as administrator**.
- Title bar must say `Administrator: Windows PowerShell`.

| Step | Instruction                                                   |
| :--- | :------------------------------------------------------------ |
| 1    | Open PowerShell as Administrator                              |
| 2    | Can be run in any directory inside the Administrator terminal |
| 3    | Paste / run the necessary code                                |

| For Starting |
| :----------- |

```powershell
# Start
# use thi code:
Start-Service PdfRenderService
# or this code:
.\daemon\pdfrenderservice.exe start
# or this code:
Restart-Service PdfRenderService      # restart
# check status
Get-Service PdfRenderService
```

| For Stopping |
| :----------- |

```powershell
# Stop
# use thi code:
Stop-Service PdfRenderService -Force
# or this code:
.\daemon\pdfrenderservice.exe stop
# check status
Get-Service PdfRenderService
```

📍 **Where:** any terminal, inside `pdf-service`
🕐 **When:** testing locally, without the Windows Service

```powershell
cd pdf-service
node server.js
```

→ visit `http://127.0.0.1:4488/health` in a browser ·

→ you must see `{"ok":true}` in the page.

→ to stop click `Ctrl+C`.

## 🟡 Step 3 — Full Reinstall (after changing daemon config)

- A normal restart (`Restart-Service`) only restarts the *process* —
  it does **not** re-read the WinSW `daemon` config (service name,
  startup type, log paths, etc). If you edit anything inside the
  `daemon` folder, the running service won't notice until it's fully
  unregistered and registered again.
- You will **not** need this often — it's not part of everyday
  start/stop. If unsure whether you need it, just re-run `install.ps1`
  from Step 1 instead; it does the same uninstall + reinstall safely.

📍 **Where:** elevated terminal, inside `pdf-service`
🕐 **When:** only after editing the `daemon` config — not for routine use

```powershell
cd pdf-service
node uninstall-service.js
node install-service.js
```

## 🟠 Step 4 — Troubleshooting

> [!WARNING]
> **"Could not find Chrome"**
> 📍 Any terminal, inside `pdf-service`
>
> ```powershell
> cd pdf-service
> dir .\.chrome-cache -Recurse -Filter chrome.exe
> ```
>
> Empty result → re-run `install.ps1` (Step 1).

> [!WARNING]
> **"Cannot open ... service on computer '.'"**
> Terminal isn't elevated. Reopen PowerShell as Administrator, then
> retry the Step 2 command.

> [!WARNING]
> **No UAC prompt at all**
> 📍 Any terminal
>
> ```powershell
> net localgroup administrators
> ```
>
> If your account isn't listed, you lack local admin rights.

> [!WARNING]
> **Service "Running" but `server.js` changes aren't applied**
> Re-run `install.ps1` (Step 1) — it always does a clean reinstall.

> [!WARNING]
> **Terminal window flashes on every PDF download**
> Not a terminal fix — open `PdfGeneratorService.php` in the backend
> and confirm it isn't calling `Browsershot::html()` directly.

> [!WARNING]
> **`StatusInvalidServiceAccount` when installing, or install silently
> fails with contradictory "already installed" / blank status**
> 📍 Elevated terminal, inside `pdf-service`
>
> Happens after the project folder is **moved or renamed** — the
> `daemon/` config still points at the old path and account. Delete
> the stale config and let the installer regenerate it:
> ```powershell
> del .\daemon\pdfrenderservice.xml
> del .\daemon\pdfrenderservice.exe.config
> powershell -ExecutionPolicy Bypass -File .\install.ps1
> ```

## 🟣 Step 5 — Connection in the system

| File                                      | Role                                                                                                                                              |
| :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`PdfGeneratorService.php`** _(backend)_ | POSTs rendered HTML (images/CSS as base64) to `http://127.0.0.1:4488/render-pdf`, gets a PDF binary back. Where PDF generation is triggered from. |
| **`.env`** _(backend)_                    | No `node_binary` / `chrome_path` / `no_sandbox` keys needed — this service owns that config.                                                      |
| **Failure behavior**                      | Service down → Laravel returns `503` immediately, no hanging request.                                                                             |
